# 诊断引擎设计说明

`analyze.js` 的全部逻辑是纯函数，输入是解析好的轨迹点与日志行，输出是问题清单与评分。
没有 DOM、没有网络，所以可以脱离浏览器单测（`selftest.mjs` 里有对应断言）。

---

## 一、为什么要做这件事

导出是条单行道：文件生成出来了，但没人读得回来。

跑完一轮路测，打开轨迹发现中间缺了一截。只看轨迹，能得出的结论只有「这里没数据」。
是 USB 掉了、天线被挡了、还是车停着没动？三种情况在轨迹上长得一模一样。

把同时段的日志一起读回来，三类立刻分得开：

- 日志那段时间**一条语句都没有** → 链路断了
- 日志有 GGA，但 `quality=0` → 定位丢了，链路是好的
- 日志正常、坐标也没怎么变 → **车停着**，什么故障都没有

这就是整个模块的价值：把「哪里断了」变成「为什么断」。

---

## 二、能读回的格式

七种，和导出格式一一对应。判格式看内容不看后缀：取文件头 8 KB 找 `<gpx` / `<kml` /
`FeatureCollection` / `$xxGGA` / 表头含 lat+lon，后缀改错了照样能读。

| 格式 | 来源 | 要点 |
|---|---|---|
| GPX | 轨迹导出 | `<trkpt>` + `<time>` + `<extensions>` 里的速度航向 |
| KML | 轨迹导出 | `LineString` 与 `gx:Track` 都认；`<Point>` 是起终点标记，**不混进轨迹** |
| GeoJSON | 轨迹导出 | 递归 Features / GeometryCollection，坐标按 `[lon, lat]` |
| 轨迹 CSV | 轨迹导出 | **按表头找列**，不认列序。Excel 另存、列打乱、多一列备注都能读 |
| NMEA 原文 | 日志导出 | RMC 的 `ddmmyy` 配 GGA/RMC 的 `hhmmss` 还原绝对时间，跨 UTC 零点自动进一天 |
| 带时间戳文本 | 日志导出 | 兼容「ISO + 语句」与纯语句混排 |
| JSONL | 日志导出 | 逐行 JSON，坏行跳过不中断 |

硬要求：**任何一行坏了都不能让整个文件失败**。解析器记下坏行数并在结果里报出来。

## 三、缺口检测与四类归因

先找缺口：相邻两点时间差 > 采样间隔中位值的 3 倍，且 > 3 秒。

再把这段时间戳丢进日志里查，看那会儿在干什么：

| 归因 | 判据 | 原因 | 严重度 |
|---|---|---|---|
| `link` 链路中断 | 日志在同时段**也断了**，一条语句都没有 | USB 线松/掉线、供电不足、串口被别的程序抢走、设备重启、后台标签页被节流 | 严重 |
| `lost` 定位丢失 | 有 GGA，但 `quality=0` 占 80% 以上 | 天线被挡、多路径、天空视野不足；冷启动前 30~60 秒也这样 | 警告 |
| `static` 静止停留 | 定位正常，**窗口内位移很小**（< 12 m） | **不是故障**。上位机按「相同坐标不重复入轨迹」，停着不动本来就不产生新点 | 提示 |
| `unrecorded` 记录丢失 | 定位正常，**位移明显** | 轨迹缓冲 20000 点被滚动覆盖，或导出时选了较短的时间范围 | 警告 |

只导了轨迹、没导日志时，缺口一律归 `unknown`，并提示「把同时段日志一起导入」。

### `static` 的判据要小心

不能只看缺口两端点的距离。长时间停车时单点漂移能攒出十几米，两端一算就变成「位移明显」，
误判成丢数据。

实际做法：取窗口内所有 GGA，算相对首点的**最大偏移**，用这个值跟 12 m 比。
用「最大偏移」而不是「累计路径」，是因为绕圈漂移的累计路径很大但包络有限——那是另一个检测项。

## 四、其它检测项

阈值全部集中在 `analyze.js` 顶部的 `TH` 对象，报告最后一章原样印出来，文档和代码不会两套数。

| 检测项 | 判据 | 级别 |
|---|---|---|
| 位置跳变 | 隐含速度 > 60 km/h 且位移 > 20 m | 警告 |
| 折返尖峰 | 出去一腿、回来一腿，两腿都 > 25 m | 警告 |
| 静止漂移 | 速度 < 4 km/h 持续 > 20 s，包络半径 > 6 m，累计路径 > 2.5 倍半径 | 提示 |
| 高程跳变 | 高程突变 > 30 m 而水平位移 < 80 m | 提示 |
| 定位降级 | GGA quality 从高等级跳到低等级 | 警告 |
| HDOP 偏高 | > 2.5 的时长占比超过 5% | 警告 |
| 链路中断 | 日志相邻两条间隔 > 4 s | 严重（>10 s）/ 警告 |
| 校验错误 | 校验不通过占比 > 0.5% | 警告 |
| 连续未定位 | `quality=0` 持续 > 5 s | 严重（>30 s）/ 警告 |
| 惯导未收敛 | 结束时 `insstatus` 仍 < 3 | 警告 |

两个实现上的坑：

- **一次「飞出去又回来」会同时命中两条「超速」和一条「折返尖峰」**，报告前必须按相邻索引合并
  （跨度 ≤ 1 视为同一处），否则一处异常报三条，看着像三处故障。
- **99.99 的 HDOP 不能直接画。** 无定位时不少设备拿它当占位符，混进统计会把曲线压成一条直线，
  所以 ≥ 99 的值在图里剔除、在统计里单列。

## 五、评分

四个维度加权，缺哪维就按剩下的重新归一化：

| 维度 | 权重 | 算法 |
|---|---|---|
| 定位可用率 | 45% | 有 `quality>0` 的时间占日志总时长 |
| 轨迹连续性 | 25% | 扣掉真异常缺口（**不含**静止停留）后的时长占比 |
| 数据链路完整性 | 20% | 日志无中断时长占比 |
| 语句校验正确率 | 10% | 100 − 错误率×4 |

A ≥ 92 / B ≥ 80 / C ≥ 65 / D。

评级之外还有一条「结论可用性」：链路完整性 < 90% 时只降级为「缺失时段不可用，其余正常」，
只有拿到 D 才判「结论不可直接采信」。

这条规则是被自己写的断言抓出来的——原来 93.1 分给 A，结论却说数据有硬伤，自相矛盾。

## 六、报告

| 格式 | 用途 |
|---|---|
| **HTML** | 完整报告，7~9 章（没有日志会少两节），内联 SVG 图。整页可编辑，双击改文字；改完自动存 localStorage；可另存 HTML、可直接打印成 PDF |
| Markdown | 贴到 issue、文档、Wiki |
| 问题清单 CSV | 12 列：级别、编号、标题、现象、原因、处置、时间、经纬度、次数 |

HTML 报告是照交付物做的：`@media print` 里隐藏按钮、去阴影、`table`/`svg` 加
`break-inside: avoid` 防止表格和图被切到两页、`@page` 留 16 mm 页边距。
所有 SVG 内联生成，断网、`file://` 直接打开也能看。

报告里的文本一律走 HTML 转义。日志原文里出现 `<script>` 只会显示成文字，不会执行。

## 七、示例数据

```bash
python3 tools/make_samples.py
```

生成 `samples/gnss-track-20261101-0930.gpx`（571 点）与
`samples/gnss-log-20261101-0930.nmea`（10,353 条），格式与上位机导出逐字对齐。
埋了六类状况：

| 时间 | 状况 | 期望诊断 |
|---|---|---|
| 120~165 s | 整段无任何语句 | 链路中断（严重） |
| 240~275 s | GGA quality=0 | 定位丢失 |
| 300 / 355 s | 飞出去又回来 | 位置跳变 ×2（各合并为 1 条） |
| 380~400 s | 校验和打乱 | 校验错误 |
| 420~470 s | 坐标完全不变 | 静止停留（提示，**不是故障**） |
| 470~560 s | 绕圈漂移 r≈9 m | 静止漂移 |

漂移段用圆周运动而不是白噪声：后者的包络半径也够大，但累计路径不够 2.5 倍半径，
正好卡在判定线下面，检测不出来。真实静止漂移就是绕真值慢慢画圈（多路径 + 电离层缓慢变化），
圆周更接近实际。

两个文件一起导入 → **11 条问题（严重 3 / 警告 5 / 提示 3），A 级 93.1 分**。
只导轨迹 → **B 级 88.3 分 / 5 条**。差异来自 `link`、`lost`、`unrecorded` 三类归因失效，
全部落到 `unknown`。

## 八、设计取舍

- **只判定，不修数据。** 不自动剔除跳点、不平滑漂移。要不要动原始数据由看报告的人决定，
  工具替人做这个决定只会掩盖问题。
- **不猜。** 只导轨迹时缺口归 `unknown`，不根据形状瞎推。宁可少给结论，不给错结论。
- **阈值单一来源。** 全部在 `TH` 里，报告印出来。改阈值只有一处要改。
